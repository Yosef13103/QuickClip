Scope is FT-01, FT-02, FT-06 and QC-003. Base is PR #7 at `0c7719410a045a7a28c7a37d1d8f14d6cc045ef7`. This branch contains discovery, the detector contract, narrow Games Settings wiring and generated fixtures.

## Discovery and migration

New Games settings default to automatic discovery. Previously persisted choices still apply. When the host starts discovery, QuickClip reads Steam install registration or its conventional install path, then local `config/libraryfolders.vdf` and `steamapps/libraryfolders.vdf`. It visits only the declared fixed-drive libraries and their `steamapps/appmanifest_*.acf` and install directories. Multiple installs for the same Steam app ID use one row. The library panel shows discovered sources. Excluding a source also vetoes executable matches under that source and the exclusion can be removed. Manual Steam roots and exact executables remain supported.

For a folder of several installs, use **Add game collection**. Use **Add one game folder** for an explicit single-install scope. To convert an existing saved single-install root, remove its approval and add it as a collection. Single-install and exact-EXE entries retain their current identity rules. Steam titles use the manifest name. Folder titles prefer useful version-resource strings from a bounded set of ranked candidates. Common crash reporters, installers, redistributables and generic updaters are excluded from discovery. Exact paths are used for matching and no EXEs are executed.

Collection discovery counts directories and EXE candidates instead of loose files. It separates shallow collection traversal and per-install candidate probing. The shared coordinator admits up to 12 work segments in a one-second window, publishes a cumulative snapshot, and yields for 250 ms before the next batch. Each segment retains the request candidate limit and an eight-second cooperative traversal limit. Steam manifest reads are limited to 8 MiB per library. The queue admits up to 4,096 segments per scan. Windows filesystem calls can outlast the cooperative limits. Scan Now resumes a paused queue without walking completed sources or installs again. Exclusion changes, opt-out and shutdown cancel in-flight work. The last published snapshot and user overrides survive. The queue lives in memory and is rebuilt after a process restart or configuration change. A source that hits a hard cap remains partial and may need a narrower approved scope.

## Startup and disposal contract

On the WPF dispatcher, after settings load and the Personal profile is confirmed, call `QuickClip.Discovery.GameCatalogRuntime.Discovery.Start()` once. It returns immediately, starts discovery when enabled, and waits 15 minutes after completion before checking again. Games Settings uses the same coordinator. On final app shutdown, call `QuickClip.Discovery.GameCatalogRuntime.Discovery.Dispose()` on that dispatcher before tearing down settings. Shutdown cancels work and prevents later publication. A disposed instance is terminal for that process. If another UI changes Games scan scope or opt-out, persist those settings and call `await GameCatalogRuntime.Discovery.SettingsChangedAsync()` on the dispatcher. Host and view do not create separate coordinators.
## Recorder adapter for Chat 1 and integration owner

`GameDetector.ForegroundObservation` reports the current observation. `GameCaptureObservation.VerifiedTarget` is the eligible exact catalog target for the armed recorder. It is populated for an explicit `Game` match or an exact candidate from a verified Steam manifest install. Legacy fullscreen/path heuristics may still supply `Target` for existing callers. They do not authorize capture through `VerifiedTarget`.

Use `GameDetector.SelectVerifiedObservation(retained, foreground, isCurrent, match)` for a verified-only state machine. Check HWND, thread, PID and process-start identity using `WindowOwner`. Retention rechecks the current catalog match, foreground-only rules, ambiguity and exclusion/offline vetoes. A Discord companion has no verified target and can leave an existing eligible game retained. `SkipAutomaticCapture` remains the existing observation veto indicator. Code should require `VerifiedTarget` independently of that flag. Source authorization, backend selection and armed/idle transitions remain the recorder's responsibility.
