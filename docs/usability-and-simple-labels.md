## Research and application comparisons
Reviewed published product documentation and UX guidance, not a new formal user-study or direct usability test of every competitor.
- NN/g, recognition rather than recall: https://www.nngroup.com/articles/usability-heuristics-complex-applications/ . Visible actions/choices relieve users from remembering hidden menus, technical concepts and multi-step sequences. Make frequent actions discoverable without learning the app.
- NN/g, aesthetic/minimalist design and progressive disclosure: https://www.nngroup.com/articles/aesthetic-minimalist-design/ . Remove extraneous copy/controls rather than reduce readability; progressively reveal infrequent options. No equal prominence for every possible feature.
- Microsoft Windows typography: https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography . Body 14 effective px/20 line height, caption 12/16, subtitle 20/28. QuickClip Personal proposes 110% default text (15.4 effective px on 14 base), independent control scaling; keep explicit preferences and DPI handling. Use dynamic resources, wrap labels, avoid fixed widths clipping. Fluent reference not mandate for pixel matching.
- Microsoft control selection: https://learn.microsoft.com/windows/apps/design/controls/combo-box ; https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings ; https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/radio-button . Dropdown for choosing one from many games/devices, buttons for direct commands, radios for visible mutually exclusive choices, checkbox for binary options and multiple tag choices. Never a generic action dropdown then Continue. Clear labels, standard icons with accessible names/tooltips.
- Gmail labels: https://support.google.com/mail/answer/118708?co=GENIE.Platform%3DDesktop . One label management entry, visible names, create and row actions, independent colors. Use name and actual state, not a label type explained in a paragraph.
- Apple Photos: https://support.apple.com/en-ie/guide/photos/pht6d60a1f1/mac/27 and Lightroom: https://helpx.adobe.com/lightroom/desktop/organize-photos/organize-photos.html . Side navigation for groups; assign keywords directly to selected items; organize existing media without physically moving it. Albums there may be many-to-many; QuickClip's virtual folder remains exclusive to avoid competing physical destinations later. Do not copy complex photo workflows.
- Medal Windows: https://support.medal.tv/support/solutions/articles/48001271487/ and https://support.medal.tv/support/solutions/articles/48000959661/ . Organize recording settings by task (quality, audio, capture/hotkeys, game settings); presets first, show actual resolution/FPS, more control behind custom; mic test and actual source selection easy to find. Do not adopt cloud/social/paid gating or game-specific events.
- Rewind pinned v0.2.6 and prior review: near-black optional theme; short state labels, recorder controls at navigation, simple preset cards, game-centric Gallery. Keep those; remove session UI per owner. No wholesale visual copy.

## Design contract
- General audience: the user's goal is capture, find, watch, edit, share, not learn database/synchronization jargon. First-use path must be operable by recognition; do not assume they read guide text. Use short sentence-case headings, visible action verbs, icons WITH labels for unfamiliar actions, state labels and examples when necessary. Familiar edit/delete/favorite/folder icons may be icon-only with accessible names/tooltips. Never rely on color alone.
- Simplify flow before shortening text: fewer modal transitions, consistent save/cancel, buttons next to objects, inline editing and search, no menus of commands disguised as dropdown. Keep unavoidable consent/consequences explicit: display capture can include messages/other windows; deleting media vs labels; current active target; expensive operation/capture restart. No hidden permission changes or ambiguous disk movement.
- Success for fast reversible action: update visible state without progress dialog/toast. Favorite changes preserve async validation, show genuine errors and prevent duplicate writes; no optimistic lie. Long exports, batch replacement, actual deletes still need useful state/cancel/recovery. Avoid UI sleeps and expensive polling.
- Body 14–16 DIP equivalent, metadata 12–13, section 18–20; existing text scale independent and 110 default for new Personal settings. Existing explicit 100% remains valid; do not globally rewrite owner theme/preferences. Check 100/125/150 DPI, 900px and ultrawide, keyboard, focus, light/dark/Broadcast/custom and wrapping. Prefer fewer rows to smaller type.
- Basic is complete normal use, not trial mode: recording master/source permission, game selection/manual add, clip length/resolution/FPS/quality, capture area, encoder fallback choice, save location/add existing clip folder, audio source/mic and test, hotkeys, recording/save notification sound/channel/position/customization, appearance, labels, editor/export. No required Advanced detour. Advanced: diagnostics, current engine lanes/logs/telemetry, unusual encoder tuning, raw geometry precision, bitrates/memory detail and specialized adjustments as appropriate. Same settings store and validated commands. Use existing controls, avoid duplicating state. Presets reuse current 720p30 Performance / 1080p60 Balanced / native60 Quality; show actual values and selected state, Custom remains available. No silent setting changes; explicit presets preserve audio, duration, permissions, codec selection. Further UI survey needed on actual hardware before visual finalization.
- Guided setup: short task-focused titles, one main action, visible choices, status/test control, progress, obvious Skip/Back/Finish; choose destination, hotkey, audio, quality, games, permission, clip feedback, review. Explicit master activation and display privacy preserved. Follow-up visual onboarding example: play sample -> press save shortcut -> show saved card -> open editor; no actual capture permission auto-grant. Optional/help affordance not mandatory tutorial.

## Labels and folders: corrected vocabulary and workflow
Internally LibraryTagDefinition (many) plus LibraryCollection (one) kept; UI 'Manage labels', Tag and Folder, not 'Collections & Tags' as a concept the user must understand. A folder label organizes Gallery only today. No on-disk change until explicit physical organization integration and consent.
Illustrative layout:
    Manage labels
    Tags help you find clips. Folders group them.
    Available for [ Half-Life 2       v ]
    [tag] Funny      Tag       [edit] [delete] [Make folder]
    [folder] Episode 1 Folder  [edit] [delete]
    [tag] Boss fight Tag       [edit] [delete] [Make folder]
    [+ Create label]   [Merge tags...] (less frequent)
    [Close]
- Scope selector All games (global labels) or specific game; preserve current scope on rebuild. Filter row should indicate global vs game-specific at point of choice. Tags colored; folders marked unmistakably with folder icon/name. Empty state 'No labels yet. Create one below.'
- Single create dialog: name, color, optional 'Show as a Gallery folder' checkbox. Explain one folder per clip and no physical movement in one short sentence. Default ordinary tag. Edits use same conceptual fields, hide inactive physical folder controls but preserve stored preferences. Row edit/delete direct; confirmation deletion only label/membership, never video.
- Make folder: transaction preserves name/color/scope and all exact existing tag assignments; remove original tag only after new exclusive collection membership commits. Refuse conflicting existing folder assignments, duplicate folder name, incompatible scopes or stale definition; no partial migration or implied replacement. Explicitly ask user to resolve conflict; no media changes. Reverse conversion to tag is not implemented; future only if safe tag capacity, duplicate names, preference references and confirmation addressed.
- Clip right-click Organize > Edit tags / Move to folder; multiple selection applies batch. Later better direct chip/label affordance on card with unified assignment picker: one folder radio group (None/Uncategorized) and checkboxes for ordinary tags, searchable, mixed state for multi-select, visible chosen label, create inline if absent, preview file path only once physical feature exists. Current split UI is intermediate; don't claim unified picker finished. Visible tags filter and folder sidebar; chip click opens folder or toggles tag filter.
- Remove active recording selection from main label manager. Optional per-game 'Clip folders...' > 'Save new clips to' None default/manual folder; advanced executable linking expander only; no mandatory setup, no new capture authorization. Useful only when playing specific episode/mod, e.g. future HL2 clips under Episode 1; ordinary user can ignore it. Future persistent recorder if adopted could expose a small current folder selector only when relevant. Never infer shared exe mode.
- No user-facing session browsing, group/timeline or automatic event integration. No changes to OBS/capture/audio B/D gates in this revision.
