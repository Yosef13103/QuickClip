# E2 — Collections and Tags (owner-approved scope)

## Product contract

- Ordinary tags: many per recording; global by default; optional game-specific availability. Tag names/colors are presentation, not capture permission or physical paths. Preserve existing tags and colors.
- Collections: zero or one per clip, global or scoped to stable game catalog identity, optional color and opt-in physical subfolder. Examples: Half-Life 2 / Episode 1, Episode 2; Terraria / Vanilla, Calamity. Ordinary tags remain independently assignable/filterable. A collection is displayed as a distinct tag-like chip, not a duplicated ordinary tag.
- Unified management surface, explicit scope and collection type, optional folder mapping. Existing tags remain global/virtual. No arbitrary default tags on all game recordings. Optional remembered current collection per game, None by default; selection affects subsequent saves only, never starts or redirects capture. Shared executable/episode context requires owner selection, not an inferred episode.
- Gallery game parent includes all recordings; expandable child collections and Uncategorized. Search/favorite/tag filters intersect selection. Use stable ids, not display names, for routing. Scoped ordinary tag names must not conflate same-named definitions from different games.
- Physical organization off by default. Opt-in new recordings use safe, explicitly configured collection subdirectory of the same game's approved recording root. Existing-recording organization is a separate preview+confirmation operation. No implicit moves after changing colors, tag names, scope, collection assignment, or folder preferences. Never duplicate media or build a hierarchy from arbitrary tags.

## Virtual organization preview

Schema 5 adds stable collection definitions and exclusive clip membership; schema 6 preserves ordinary tag IDs, colors and memberships as global definitions while introducing independent game-scoped definitions. Global and scoped tags may share a name, but a clip can carry only one definition of that name; exact-definition replacement resolves conflicts. Legacy name-only imports stay global. Free-text edits preserve existing tag identity; new text prefers an applicable scoped definition then global. Explicit typed selection uses stable IDs, rejects incompatible scope and stale metadata, and supports atomic bounded batches.

Gallery's unified manager creates, edits and deletes both types. Collection deletion preserves files and ordinary tags; definition deletion removes memberships, including offline rows. Gallery game parents and expandable children are virtual, with Uncategorized and identity-based filtering. Existing unknown-game clips can be explicitly associated with a catalog game during collection assignment; conflicting known IDs are never replaced by that flow. No filename or display-name inference. Search, favorites and tag filters intersect the selected folder.

Games offers collection management, game-specific tag creation and remembered None/manual/automatic collection choices. Automatic selection is opt-in, exact verified gameplay-executable linking only; no launcher guessing, mod detection framework or capture authorization changes. A missing or ambiguous match stays Uncategorized. New replay sidecars carry game and requested collection IDs; index publication checks scope and existence, including a guarded repair for a fresh-save/index race. Manual desktop saves are not assigned a game collection. Changing a preference does not alter earlier clips.

Optional folder leaf validation is implemented, but physical routing remains inert. Current UI is a functional dialog-based preview, not final visual/hardware acceptance. No production database migration authorized.

## Verified related-title folders (owner correction)
Discovery derives related titles from verified same-provider claims at the exact same single install root, identical nonempty eligible renderer sets, and a unique unqualified parent title followed by a title separator in each child name. No hardcoded game IDs, executable names or folder names. Qualified suffixes are read from provider titles; unrelated or duplicate generic title claims, overlapping but different renderer sets, separate installs, and ambiguous parent chains remain unresolved. Ordinary cross-store identity aliases do not generate folders. This is conservative inferred grouping, not a universal provider relationship API. On Gallery/label/folder-settings reads, materialize verified related titles as game-scoped virtual folders. Existing same-scope same-name folder is adopted without changing its identity, membership, color or folder preference. Schema 7 stores a parent/title-to-folder link; rename preserves link, deletion leaves a NULL tombstone and discovery cannot recreate it. No automatic membership or preference changes; root is default, manual selection explicitly remembered, existing explicit preferences retained. Automatic executable link behavior remains opt-in and cannot infer episodes sharing a renderer. Folders appear in Games > Clip folders even before there are recordings; Gallery lists game groups with clips. No physical file moves. v6 upgrade and v7 deletion/rename/concurrency safety require isolated acceptance; do not reuse upgraded profile in v6 candidates without restoring backup. B migration integration, historical episode identity reconciliation, real saves and independent review remain outstanding.
