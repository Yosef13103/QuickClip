## Shared background activity surface
Use the bottom status strip for long-running operations without blocking navigation, replacing recording status or interrupting capture. Existing per-page progress and error messages remain authoritative. BackgroundActivity.Begin(label) returns a short-lived IDisposable lease; use a using scope for the whole asynchronous operation, Report(label, fraction?) for actual progress or named stages, and dispose on success, cancellation or failure. Results are sampled using the existing window status timer; sub-350ms tasks do not appear, and the strip is collapsed when no eligible work remains. Unknown totals use indeterminate progress and actual scan counts; known totals use determinate progress. Several operations show the oldest and a +N indicator; hover/click for the live list. Reduced-motion mode shows text instead of indeterminate animation. No dedicated worker, timer, disk history or per-frame instrumentation. Initial coverage: Gallery refresh (including index counts, reading rows, legacy scan), immediately refresh after successfully adding/removing/changing Gallery sources even from Settings, library storage checks, bulk Gallery actions, editor exports, clip saves including hotkeys, and update downloads. Existing instant-share indicator remains separate. Wave 2's evolving game-discovery pipeline should register its explicit/long-running discovery jobs using the same lease API, not every foreground poll. Additional slow operations should adopt the contract only where meaningful; no claim of universal instrumentation. Test large generated clip folders, concurrent export/scan, cancellation/failure, switching pages, and narrow/high-DPI window layouts. Do not use owner media for destructive fixtures.

## Camera overlays — native research gate (Wave 3, after GPU capture baseline)
Historical proposal, narrowed by the 2026-11-19 owner decision to one optional camera: composite a webcam feed composited in saved clips, visual drag/resize/drop over the output canvas rather than fixed corners. Explicit opt-in by device, no camera activation merely from discovery or opening settings; preview only by deliberate action and stop on exit, master off or no authorized capture. Persist stable device IDs and normalized output coordinates, size/aspect/crop, z-order, optional mirror; support per-camera enable/disable, keyboard/numeric placement alternative, safe disconnected devices, rotation/crop/ultrawide/scaled canvas. Research Media Foundation capture and D3D11 GPU surfaces/conversion, timestamp synchronization, format/driver compatibility, shared textures, single compositor before encoder, minimal overhead; benchmark zero-camera baseline and one/multiple cameras separately. No CPU readback or re-encoding ordinary clips by default, no camera audio without distinct explicit choice. Preserve hybrid audio/ring, source permission and protected media. Camera failure should not end otherwise healthy game recording; clear truthful feedback; no stale/private frame carryover. Camera baked into video for initial proposal (not separately editable tracks). Research/demo/fixture tests then real webcam and capture hardware acceptance. Do not introduce driver/security bypasses or unreviewed dependencies. No dependency on the canceled Wave 4 multi-display compositor; do not implement in this maintenance PR.
