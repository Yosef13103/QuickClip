# Post-v1.1.0 maintenance checkpoint

Independent PR based on published Personal v1.1.0 (6de4ad684f4268b685c630d639977c439bf557ed), not the Wave 2 worktree. Coordinate integration before merging any overlapping Wave 2 work. No version bump/publication without owner approval.

- Named custom themes: import valid readable JSON into a profile-local collection; select saved themes from the existing Theme picker; edits preserve other themes; confirm same-name replacement and removal. Legacy single CustomThemeJson is migrated into the collection, and remains the active palette for legacy readers. Maximum 128 validated palettes. Original files are never modified. Low-contrast imports remain drafts until corrected.
- The existing selected-display switch previously excluded automatic games only. Under the owner's clarified requirement, existing ExcludedGameDisplays entries now also veto manual capture, including tray selection and cycling. A blocked active manual display loses its session grant and reconciles to an eligible authorized game or standby/unavailable. Global recording remains enabled. Re-enabling a display is not a new automatic capture grant; manual capture still requires explicit selection. Do not silently substitute an unapproved capture target. Test switching both monitors, excluding active/idle targets, hotkey/tray paths, restart and game-following.
- Installer remains per-user (PrivilegesRequired=lowest, same AppId, HKCU registration). Choose any writable local folder, e.g. F:\Games\QuickClip Personal; do not install at a drive root or automatically change ACLs/elevate. Destination preflight checks writable existing folder or nearest existing ancestor and explains failures before payload extraction. It cannot predict locked existing binaries, antivirus or every downstream ACL. CI uses a SUBST drive letter and an actual packaged installer on a disposable runner, not a physical disk ACL reproduction. Request the exact failing path and Setup /LOG output if Error 5 persists. Installer upgrade should normally keep the existing path and account.

Manual acceptance remains distinct from headless CI: verify multiple imported themes persist after restart and original file removal, same-name confirmation and removal; verify physical display exclusions under recording; try a writable real non-C drive and a denied directory with the affected user's permissions. Published v1.1.0 remains unchanged.

## Shared background activity surface
Use the bottom status strip for long-running operations without blocking navigation, replacing recording status or interrupting capture. Existing per-page progress and error messages remain authoritative. BackgroundActivity.Begin(label) returns a short-lived IDisposable lease; use a using scope for the whole asynchronous operation, Report(label, fraction?) for actual progress or named stages, and dispose on success, cancellation or failure. Results are sampled using the existing window status timer; sub-350ms tasks do not appear, and the strip is collapsed when no eligible work remains. Unknown totals use indeterminate progress and actual scan counts; known totals use determinate progress. Several operations show the oldest and a +N indicator; hover/click for the live list. Reduced-motion mode shows text instead of indeterminate animation. No dedicated worker, timer, disk history or per-frame instrumentation. Initial coverage: Gallery refresh (including index counts, reading rows, legacy scan), immediately refresh after successfully adding/removing/changing Gallery sources even from Settings, library storage checks, bulk Gallery actions, editor exports, clip saves including hotkeys, and update downloads. Existing instant-share indicator remains separate. Wave 2's evolving game-discovery pipeline should register its explicit/long-running discovery jobs using the same lease API, not every foreground poll. Additional slow operations should adopt the contract only where meaningful; no claim of universal instrumentation. Test large generated clip folders, concurrent export/scan, cancellation/failure, switching pages, and narrow/high-DPI window layouts. Do not use owner media for destructive fixtures.
