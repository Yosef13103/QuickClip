# QuickClip Personal library index

The catalog is an opt-in service. A host supplies approved roots and calls reconciliation explicitly. The existing Gallery, Editor and Projects workflows still use their current paths. `LibraryIndex.ForCurrentProfile()` keeps the database at `library/clips.sqlite3` under the Personal local-data directory, including portable profiles. It reads existing `clip-details` records from that profile. The constructor accepts an absolute database path and optional legacy metadata directory and header reader for fixtures or a different host.

## Schema and deployment

Schema 1 contains `roots` and `clips`. It tracks category, path and normalized lookup key, file identity and stat cache, capture date and provenance, display fields and overrides, availability, favorite, metadata revision, original/export link, session and optional opaque game catalog ID. Schema 2 adds `tags`, `clip_tags` and `bookmarks`. Migrations use one transaction, SQLite application and schema version checks, enforced foreign keys, WAL and a five-second busy timeout. The provider is `Microsoft.Data.Sqlite` 10.0.14 with its NuGet SQLitePCLRaw bundle. A Windows x64 publish carries `e_sqlite3.dll` with the managed assemblies. Ship it with the publish output. [Microsoft.Data.Sqlite package](https://www.nuget.org/packages/Microsoft.Data.Sqlite/10.0.14) · [Native SQLite bundle documentation](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/custom-versions)

## Import and reconciliation

- Register a specific local directory with `RegisterRootAsync(directory, category, exclusions, cancellationToken)`. Exclusions are root-relative directories. Use `ImportedFinished` for the finished library, `Legacy` for separately approved older media, and explicitly register distinct `QuickClipOriginal` and `Export` roots when managed storage is ready. The ordinary scan skips nested `QuickClip`, Projects, caches, raw `SteelSeries Moments`, hidden/system entries, reparse points and common partial filenames. Registration never creates the media directory.
- Call `ReconcileAsync(rootId, options, cancellationToken)` from a serialized background job per root. The default bound is 100,000 entries and 16 directory levels per scan. Scan results report limits, access errors, files seen, header reads and missing transitions. When `Complete` is false, schedule smaller subdirectory scopes or raise a bound deliberately. Check the root and its volume identity before committing. A missing, inaccessible or changed-volume root is unavailable. Rows and annotations survive.
- Rename repair uses the volume and Windows file ID, corroborated by creation time and a displaced or absent old path. Moves within a root retain the ID when the match is unambiguous. Copies, cross-root moves, replacement files and ambiguous matches can create separate IDs. An old ID and its annotations remain in the catalog. The fallback on filesystems without stable file IDs is path plus exact stats. Reconciliation uses a scan revision to reject a stale commit. Unchanged files reuse cached header facts and skip row updates.
- Initial capture time comes from a stat-verified legacy JSON record, then the embedded MP4/MOV/M4V timestamp, then the earlier of creation and modification time. The row records provenance and distinguishes stale legacy stats from unreadable JSON. Initial legacy import preserves valid game and title corrections. Later rescans and annotation edits preserve the stored capture time. The old JSON stays available to the current Gallery. MKV/WebM get indexed with unknown duration by default. The existing bounded probe path can supply a duration reader in a later integration.
- A watch event should only schedule reconciliation. Use the old and new parent paths for a rename and use the registered root on watcher overflow. Coalesce bursts and cancel stale jobs. Callers choose when to retry a partial scan or a locked file. Root removal and editing saved exclusions need dedicated service operations before Settings exposes those controls.

## Integration touchpoints

1. In Personal startup, create one catalog service through `ForCurrentProfile()` after the profile is chosen. Add explicit opt-in controls in Settings for approved roots and exclusions. Start scans only on approved roots and pass the host cancellation token. Keep the SQLite operations off the dispatcher and surface failed or partial jobs.
2. In `GalleryView.ReloadAsync` and `ShowFolder`, map `QueryClipsAsync(ClipQuery, ct)` pages to gallery cards. Use `IndexedClip.Id` for row identity and `Path` for play/edit/reveal. The query supports literal normalized title/game search, exact game or game ID, tag, favorite, category, root, availability, capture-date interval, duration range and stable sorting. Set `Availability = Available` for the ordinary gallery and expose missing/unavailable rows only in a maintenance view. The default page size is 50 and the limit is 200. Continue using `ProjectLibrary` for project membership. Translate the current `Watch` callbacks into the scoped repair described above.
3. In `GalleryView.EditClipDetails_Click` and future tag/favorite controls, use `GetAnnotationsAsync`, `SetClipDetailsAsync`, `SetTagsAsync` and `SetFavoriteAsync`. Pass the loaded revision and refresh on `LibraryConflictException`. Pass blank title/game to reset their path-derived values. Store game-catalog IDs verbatim as opaque keys. Keep the current JSON as an import source until catalog-backed reads and writes have been verified end to end.
4. In the Editor timeline, load bookmarks via `GetAnnotationsAsync` and save through `UpsertBookmarkAsync` or `DeleteBookmarkAsync`. `ClipBookmark.Offset` is measured from the first encoded video frame. Mutations require a known duration and an offset in `[0, duration)`. Callers supply stable bookmark IDs and can also supply session ID and exact marker timestamp. An unknown duration requires a probe before accepting a bookmark. Conflicts and invalid offsets roll back.
5. In `Recorder.SaveClipAsync`, extend the receipt after `ClipNaming.Publish` succeeds. Include the published path, requested and actual durations, encoded capture timestamps if measurable, game, session and the marker offsets actually retained. Add a single-file receipt ingest API to the service so row creation, authoritative capture facts and retained markers can commit together. Until then, the current published file and legacy metadata can be indexed with a scoped scan. In the Editor export path, submit the receipt after staging is published successfully, then associate the indexed export and original with `SetClipAssociationAsync`. A database failure should report a catalog error while the successfully saved file remains playable. Show finalization separately from indexing and never infer it from trimming metadata.

## Storage and recovery

`GetStorageInventoryAsync(ct)` returns indexed available counts and logical bytes by root/category/game, known-identity logical bytes deduplicated across hard links, unidentified logical bytes, free space per reachable root, missing and unavailable counts, and the count of available originals without an available linked export. Files under separate roots on the same volume share the same free space. The inventory excludes unregistered files, Projects and caches. Cache/project estimates and unindexed orphan enumeration are separate follow-ups. Use `StorageInventory.EstimateBytes` for a bitrate-based forecast. It estimates payload bytes before muxing overhead. SQLite byte totals do not measure physical allocation or independently verify export playability.

`BackupAsync(destination, ct)` creates a new SQLite snapshot via the online backup API. Choose a fresh filename outside the media roots and verify the backup by opening it separately and checking the expected roots, clips and annotations. In a recovery workflow, stop catalog writers, retain the damaged DB and its WAL/SHM siblings for diagnosis, and open a verified backup at a new path. A failed backup may leave an incomplete destination. SQLite errors propagate and media remain independently playable. The service performs no retention, deletion, project-copy management or automatic corruption repair.
