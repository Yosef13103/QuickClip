# Optional recording status icons

This scoped change replaces the experimental red recording dot with original, theme-independent, translucent camera and microphone glyphs. The existing opt-in preference and anchor are retained; icons are shown only during actual game or manual desktop replay recording on the captured display. Mic status has its own on/off switch under Notifications. Both are independent of transient clip notifications. Old profiles that opted into the dot see the camera instead; the mic glyph appears only if microphone lanes are selected and the mic-status switch is enabled.

The microphone glyph is hidden with no selection, white when every selected input has captured audible PCM recently, red if any selected input is quiet, missing or failing. A 2.5-second per-device hold avoids a flash between words; this measures signal, not device health, and does not assert audio is present in the final encoded file. Both endpoint and legacy mic routing are supported using the existing nonblocking native signal API. No new audio capture, native changes, diagnostics files, or independent meter when the HUD is off or no mic is enabled. Only an opted-in live HUD with selected mics samples at 150ms; the UI changes color only on a state transition. Reset at epoch/selection changes. Capture-exclusion API success is required, not proof of exclusion under DDA or exclusive fullscreen.

Validation: focused pure policy tests, both strict Windows profiles on combined candidate, and supervised nonprivate clips on both monitors/DPI scales. Verify camera position, visibility on desktop/game, disabled state, no microphone selected, one live and one muted/missing microphone, both receiving signal, default+explicit duplicate, silence hold, master off, capture recovery, and absence of HUD from saved replay. If captured or invisible, disable the experimental HUD; investigate backend compatibility rather than promise universal exclusion.
