# Optional recording status icons

This scoped change replaces the experimental red recording dot with original, theme-independent, translucent camera and microphone glyphs. The existing opt-in preference and anchor are retained; icons are shown only during actual game or manual desktop replay recording on the captured display. Mic status has its own on/off switch under Notifications. Both are independent of transient clip notifications. Old profiles that opted into the dot see the camera instead; the mic glyph appears only if microphone lanes are selected and the mic-status switch is enabled.

The microphone glyph is hidden with no selection, amber while checking, red after ten seconds if any selected input has not produced captured audible PCM, and white as soon as every input has independently produced sound. White latches for the capture epoch even in prolonged silence or later device failure; it is startup verification, not a live health monitor or proof of final encoded audio. Both endpoint and legacy mic routing are supported using the existing nonblocking native signal API. No new audio capture, native changes, diagnostics files, or independent meter when the HUD is off or no mic is enabled. Only an opted-in live HUD with unverified selected mics samples at 150ms; polling stops entirely when all are confirmed, and the UI changes color only on a state transition. Reset at epoch/selection changes. Capture-exclusion API success is required, not proof of exclusion under DDA or exclusive fullscreen.

Validation: focused pure policy tests, both strict Windows profiles on combined candidate, and supervised nonprivate clips on both monitors/DPI scales. Verify camera position, visibility on desktop/game, disabled state, no microphone selected, one live and one muted/missing microphone, both receiving signal, default+explicit duplicate, ten-second deadline, recovery after red, prolonged silence after white, master off, capture recovery, and absence of HUD from saved replay. If captured or invisible, disable the experimental HUD; investigate backend compatibility rather than promise universal exclusion.
