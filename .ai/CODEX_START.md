## User-visible requirements
1. Low-overhead single replay buffer, **game first and sticky**: game should continue being captured while Discord gains foreground. Discord should not hijack the buffer; user often alt-tabs to Discord call windows/popouts but chiefly wants game clips. User-selectable capture priority and per-app rules. When not playing, allow selected desktop or monitor-containing-Discord fallback. Identify Discord popout windows and user-configured companion applications robustly; provide manual pin/override. Don't hardcode a process name `Update` as game. No arbitrary full-screen monitor hijacks.
2. Optional later: save both game and Discord at the same instant from two independent buffers; optional all-monitor independent buffers or composite frame layout. Different display sizes must remain non-distorted. **Keep OFF by default** and show estimated RAM/VRAM/GPU encode and privacy cost. Save game only, Discord only or both with separate hotkeys/commands. It is fine to schedule this after single capture and audio are validated.
3. Native 3440×1440 and native 1920×1080 recording, independently selectable FPS/resolution/codec/bitrate quality. Existing editor retained with 0–200% gain for each actual audio stream, mute, solo, waveform, crop, trim, no unnecessary re-encode, and adjustable export-size targets including custom values with expected file size shown.
4. **Audio source selection by arbitrary Windows endpoints**: capture multiple playback render endpoints via WASAPI loopback plus selected mic/capture endpoints. Must run on Windows 10 22H2. Preserve audio as independently editable named tracks through recording, preview, export; support device hot-unplug/reconnect, stream timing and duplicate-signal warnings. Existing QuickClip process-audio split `AudioRouting.SeparateTracks = false` is not the relevant mechanism; don't flip it blindly.
5. **Clip identity**: creation/capture time NEVER changes when the clip is trimmed or exported. Names configurable with `{game}`, `{yyyy-MM-dd}`, `{HH-mm-ss}`, `{custom_title}`, source etc, including these templates: `{game}__{yyyy-MM-dd}__{HH-mm-ss}.mp4` for unnamed master; `{game}__{yyyy-MM-dd}__{HH-mm-ss}_{custom_title}.mp4` or `{game}_{custom_title}__{yyyy-MM-dd}-{HH-mm-ss}.mp4` for named clips. Windows-safe sanitize/collision handling. Users can rename a clip and fix its game categorization permanently or by rule.
6. **Library**: SQLite indexed but media remains standard independent video files. Search/filter by game, arbitrary tags, favorite/star, date, original/edited status, type/source, name; editable title/game; correct chronology; accurate original-vs-export storage accounting. Support non-destructive edit recipe/master and optional clean-up of masters with clear policy, preview/undo and opt-in only. Never delete 113 GB legacy originals by default.
7. **Moments migration**: build read-only inspector and dry-run plan, identify metadata and embedded/separate chat/mic tracks using ffprobe and format evidence rather than assumptions.
