# Validation, evidence and integration

## Q1. Preflight and safe environments
On the owner workspace, read `docs/local-workspace.md`; use the shared SDK/dependencies/native cache wrapper, never force-provision through a junction. CI uses clean pinned inputs. Inspect repo docs/current scripts, `git status --short`, branch/remotes, worktrees, current exact refs, open PRs, disk/SDK/deps; fetch where allowed. Review `.codex` and nearest instruction overrides for stale conflicts. Use x64 SDK pinned by repo (prior 10.0.403), native tools/deps; `scripts/get-deps.ps1` and `scripts/dev.ps1` only after inspecting effects. If Python broken use verified interpreter, not a product fix. Windows commands from repo root. Explicitly quit existing tray app yourself before test; don't kill preexisting production process. Set `QUICKCLIP_PERSONAL_DATA_DIR` to a fresh isolated `.quickclip-local/wave2-profile` (distinct profile per run if appropriate), use generated media and disable capture/update/scan for ordinary UI and headless baseline. Confirm profile actually applied and IPC cannot target production; clear env after. No installer/startup/Explorer tests against real system without authorization. Avoid actual game launch or recording without owner.

## Q2. Validation layers and acceptance
1. Focused regression fixtures as early as possible; include denied cases, cancellation/failure, persistence and concurrency where relevant. Use current repo test conventions and honest skip counts. No broad test rewrites for green output.
2. At coherent candidate: strict Release builds and applicable full Windows headless suites for **Personal** (Upstream acceptance retired by owner; optional historical comparison only), using commands from current CI/development doc; don't invent switches. At verified baseline `docs/development.md` gives `dotnet test QuickClip.slnx -p:RequireCaptureEngine=true`; inspect current profile-specific workflow arguments. Live capture tests require explicit opt-in (`QUICKCLIP_TEST_CAPTURE`) and supervision. Separate native tests, FFprobe track/geometry/duration, synthetic dependency/installer tests as relevant. CI for exact candidate SHA, record job/run URL and conclusion; check integrated candidate again after relevant change. Do not endlessly poll CI or rerun unrelated checks.
3. Independent targeted diff review (prefer reviewer without implementation bias): scope, consent/data loss, source truth, race/lifetime/rollback, backward compatibility, license and regressions. Fix findings and invalidate stale evidence. No fake review on same author's self-check.
4. Hardware owner gates: Discovery D5; GPU/monitor behavior, genuine listening, FPS, installer actual upgrade and failures, notification position/themes/capture exclusion. Use short explicit supervised sessions, scratch profiles and synthetic content. No private audio/media upload. Actual observed source, outcome, tester and SHA/build recorded. Headless tests do not prove any of these.
5. Stable integration only with exact owner authorization; candidate must have required evidence and all blockers resolved or explicitly documented as non-shipping/deferred. Review dependency graph/PR ancestry, CI, conflict and release workflow. Merging `custom/main` may publish: do not merge merely to test! No version/release workflow changes till scope accepted; stable-only tags, preserve prior assets/branches. No automatic nightlies, rollback/downgrade, deletion, merge or publication. Test installer/portable side-by-side in disposable environment and actual approved owner upgrade; retain Personal identity and clips/settings. Verify rights for packaged assets.

## Q3. Benchmark protocol (W2-A minimal; W2-P fuller)
Measure baseline before candidate changes where practical; if owner not available, preserve exact baseline SHA and plan, do not block discovery on full GPU benchmark. Compare v1.1.0 baseline vs candidate under matched settings/workload, upstream optional only if clearly labeled. Inspect old `scripts/Run-QuickClip-Memory-Benchmark.bat`/PowerShell if present; historical script compared stale preview, must substitute current refs/snapshots deliberately. Old upstream variant modified settings/log paths and disabled default capture; not stock binary. Build outside measured interval; isolate profiles, disable scanning and recording for idle run. Never run upstream first-run capture unsupervised. No branch resets for snapshots.

- Idle: fixed warmup then >=60s visible and >=60s actual close-to-tray; label minimize separately. Armed-no-game and scanning separate. Active game: matched resolution/FPS/codec/replay/audio/dev settings, same workload, repeat runs/scenario order where possible and note variation. Compare diagnostics off/on, sustained runs, repeated editor open/close and save requests. Real GPU capture only owner-supervised.
- Record exact build SHA/variant, OS/driver/SDK, machine, profile/settings, warmup/sample interval/duration, runs, workload, raw measurements and median/p95. CPU convention (one-core vs total), private bytes/WS, native/managed allocations, handles/threads/GDI, IO, GPU 3D/video encode/VRAM, FPS/1% lows/frame pacing, drops, save latency, actual replay duration. For game load compare controlled baseline, don't infer from headless metrics. No speculative performance promise, no fake zero-instruction cost. Report plateau/variance; use counters/ETW only where helpful.
- Verify the current OS, CPU, GPU, display configuration and encoder capability. Record device specifics in private evidence. Synthetic benchmarks do not measure actual gameplay.

## Q4. Evidence / board format
For each task update only relevant entry in TASKS.json. Candidate SHA, implementation status, gate result per type, evidence reference, blocker/next action. Before commit record `working_tree_uncommitted` rather than falsely binding to HEAD; after commit/CI record exact SHA. Evidence from relevant earlier SHA permissible as historical but not current pass. Keep private raw output in `.quickclip-local/agent/evidence/<task>/`; sanitized summary in board or PR. A result contains test command/scenario, expected/observed, count/skip or metrics, date, tester, SHA or uncommitted, and sanitized location/link. Mark absent tools/environment as blocked, unavailable hardware pending. N/A requires reason. Gate invalidation for relevant changes; stable build status isn't hardware acceptance. Never count completion percentage from task count.

## Q5. Reusable product smoke set (select impacted scenarios)
- Capture: master off, armed idle, explicit manual display switch, game priority, exclusions, source recovery, geometry, GPU/encoder and hybrid audio track correctness, save failure/recovery, overlapping markers, real duration. No actual protected archive touching.
- Editor/Gallery: generated clip, independent track controls, trim/crop/full mix vs stems exports, captured UTC, autosave metadata, deletion/Undo and missing source, index rebuild/overlapping roots, large library, muted hover and cleanup on close, minimize/restore/fullscreen/theme.
- UI: Dark/AMOLED/Slate/Light/Custom, 100/125/150% scale, monitor negative origin, actual physical banner/image edge margins, supported animation duration/alpha, reduced motion, click-through/non-activation, sound routing and failure feedback; preserve Wave 1.
- Reliability: restart/crash/cancel, offline libraries, disconnect/sleep/resume, busy CPU, burst save, driver reset (only if safe owner-controlled), no leaks, dev/profile isolation, supported upgrade/rollback. Retain essential failure logs even when verbose diagnostics disabled.
